## 2026-02-18 - CLI Interaction Defaults: Reducing Friction on Gateway Commands
**Learning:** CLI commands designed to onboard or authenticate users (gateway commands) should default to interactive mode rather than requiring an explicit `-i` / `--interactive` flag. Forcing a flag creates a common trap where users encounter a usage error on their first try (e.g., typing `agents-cli login` and getting "requires interactive mode"). Defaulting to interactive, with clear support for negation (e.g., `--non-interactive`) and specific status sub-actions, eliminates first-time friction and aligns command-line behavior with user expectations of interactive helpers.
**Action:** When designing or refactoring CLI gateway commands (e.g., auth, setup, scaffolding, initialization), ensure they default to an interactive guided flow, providing clean `--non-interactive` overrides and explicit status options rather than failing with standard usage errors.
